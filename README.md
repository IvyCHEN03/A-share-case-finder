# A股偏门案例检索 Skill · 使用说明

一套让 Claude 按资深投行/PE 方法论帮你检索 A 股 IPO/再融资/并购"偏门案例、边界案例、监管口径不明先例"的工具。核心是把"先查监管规则→拆解口径→高召回找候选→回一手文件核实→分层结论"这套顶级 banker 的工作纪律固化下来，确保每个结论都能回溯到交易所/证监会的原始披露文件。

---

## 一、这个 Skill 解决什么问题

日常能被 Wind/Choice 一键筛出来的案例不需要它。它专门对付这类需求：

- "三类股东 / 对赌清理 / 突击入股……这种边界情形有没有可参照的先例？"
- "科创板有没有上市前发明专利极少的先例？"
- "A股IPO在审期间是否存在新增股权激励的案例？"

这些问题的共同点：常规数据库搜不出来、需要人工判断口径、结论必须能拿去放进 IC 材料经得起内核和监管推敲。

---

## 二、如何安装

**claude.ai 网页/桌面/App（Pro/Max/Team/Enterprise）**
Settings → Capabilities/Skills（不同版本名称略有差异）→ 上传本 zip，需开启代码执行（Code execution）。安装后 Claude 会根据你的提问自动匹配调用。

**Claude Code / Cowork**
把解压后的 `a-share-corner-case-finder/` 文件夹放到 `~/.claude/skills/`（个人级）或项目内 `.claude/skills/`（项目级）即可，无需上传。

装好后可问一句"你现在能用哪些skill"确认已识别。

---

## 三、如何调用（三种方式，从简到细）

**方式一：自然语言直接问（最常用）**
Skill 靠描述自动匹配，你只要正常提问，句子里带上"科创板""案例/先例""审核""偏门"等词就会触发：

> "帮我找A股科创板上市前发明专利少于20项的已上市案例，注册制以来，终止项目单列。"

**方式二：显式点名（最稳妥）**
不确定是否触发时，直接点名：

> "用'A股偏门案例检索'这个skill，帮我查发行人与控股股东历史期内共有产权的处理先例。"

**方式三：先填口径单再检索（最专业，强烈推荐用于正式项目）**
让 Claude 先把 `templates/case_request_template.md` 的口径单过一遍再动手。你补得越清楚（尤其"严格口径"和"排除项"两栏），结果越准。可以直接说：

> "按口径单跟我确认一下检索口径再开始。严格口径是……，要不要包含终止项目？"

## 四、一次高质量检索会经历什么（对应 Skill 的 Step 0–7）

理解这套流程，能帮你判断 Claude 给的结果处在哪个可信度档位：

1. **Step 0 先查监管规则**——Claude 会先告诉你这件事监管到底怎么规定的（明确禁止/允许但需说明/有豁免清单），并据此判断"这类案例应该多还是少、该找正面还是反面先例"。这一步是整套方法论的地基，你会看到 Claude 先给规则再给案例。
2. **Step 1–2 定口径、拆检索词**——和你确认板块、时间、阈值、排除项。
3. **Step 3 高召回找候选**——优先扫招股书里的标准化披露表格，并用知名大案例反查交叉验证，不会只抄一篇律所文章的举例。
4. **Step 4–5 回一手文件核实**——去交易所/巨潮调原始 PDF 读条款。**这是最耗时也最值钱的一步。**
5. **Step 6 分层结论**——每个案例标 A/B/C/D 四档（见下）。
6. **Step 7 交付**——结论先行的 Memo，可直接用。

---

## 五、读懂结果里的核实档位（关键）

Claude 交付时会给每个案例标注核实层级，**这决定了你能不能直接引用**：

| 档位 | 含义 | 能否直接用 |
|---|---|---|
| **A类** | 严格符合，且已读到一手文件条款原文 | ✅ 可直接引用 |
| **B类** | 高度接近但缺一项条件，或一手文件仅"定位到"未"读到原文" | ⚠️ 需补最后一步核实 |
| **C类** | 形似而实质不符（已附排除理由） | ❌ 用作反例/排除 |
| **D类** | 仅二手线索，未做一手核验 | ❌ 仅供线索，勿引用 |

**特别注意"定位到文件"≠"读到条款原文"**：Claude 找到了那份招股书、甚至定位到了第153页，但还没实际读到那一页的文字，只能算 B 档。这个区分是刻意保留的诚实机制——你看到 B 档时，就知道还差最后一步"把那页读出来"，可以直接让 Claude 补上。

---

## 六、给使用者的三条建议

1. **口径单值得花两分钟填。** 尤其"排除项"——很多检索翻车是因为把"形似实不符"的情形（如把"集团商标授权"当成"共有产权"）混了进来。
2. **要求 Claude 落到 A 档再引用。** 如果它给了一堆 B/D 档就收尾，直接说"把排名前2个案例的一手条款原文读出来坐实成A档"。
3. **让案例库滚起来。** 每做完一类检索，让 Claude 把核实过的案例补进 `references/verified-cases.md`。用得越多，这个库越值钱，下次同类问题直接复用。

---

## 七、边界

本 Skill 是研究与检索工具，不替代律师法律意见、保荐机构内核意见或与监管的正式沟通。所有对外结论以标注了一手文件出处、经核实的 A 档结果为准。

## 九、关于案例库（公开版说明）

本仓库发布时，`references/verified-cases.md` 为**空白模板**——它是给你在实际使用中沉淀经一手核验案例用的。经核验的真实案例、具体数字与核实进度属于使用者的私有研究成果，不随本方法论公开。若你在本地维护含真实数据的版本，建议命名为 `verified-cases.local.md`（已在 `.gitignore` 中忽略），避免误提交到公开仓库。

本 Skill 公开的是**方法论与工作纪律**，不含任何特定项目、机构或个人的信息。
