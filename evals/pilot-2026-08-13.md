# 2026-08-13 Pilot：同模型下通用检索 vs Skill工作流

## 测试定位

ChatGPT通用检索和Codex加载Skill均使用GPT-5.6-sol，因此本Pilot控制了基础模型变量。对比对象是：

```text
GPT-5.6-sol + 通用对话/临时Prompt
vs
GPT-5.6-sol + Codex执行环境 + 固化Skill工作流
```

这能够支持“同一基础模型下，结构化上下文与工作流封装改善了本案例表现”的结论。但ChatGPT与Codex的搜索工具、任务执行方式和上下文机制仍可能不同，所以不能把全部差异严格归因于Skill文件本身。若要测量Skill净增益，应补做“Codex GPT-5.6-sol不加载Skill”组。

## 今天案例的六个测试节点

这是一条逐步收紧口径的纵向压力测试。后续节点会泄漏前序候选和答案，因此六个节点不能冒充六道独立未见题。

| ID | 测试节点 | 主要能力 | Gold行为 |
|---|---|---|---|
| P01 | 外部投资人与员工平台存在一致行动或表决权绑定，并成功上市 | 初始口径拆解、候选发现 | 先拆主体、关系、时点和上市状态，不直接堆公司名 |
| P02 | 两类问题是“或”：共同签一致行动协议；外部投资人向平台委托表决权 | 逻辑运算和协议方向 | 两条检索路径分别作答，不互相替代 |
| P03 | 复核强一股份、赛微微电子、埃泰克、安凯微等候选 | 必要条件排除 | 不因出现“一致行动”字样就判严格命中 |
| P04 | 新增“最好是无实际控制人” | 条件硬度、动态重排 | 明确它是硬性条件还是排序偏好；若按硬条件，重评全部旧候选 |
| P05 | 找到并核验微电生理 | 严格命中和一手证据 | 识别无实控人、外部投资人、员工平台、直接一致行动和成功上市 |
| P06 | 改问外部投资人将直接持股的表决权委托给员工平台 | 对抗性方向测试 | 微电生理由A-E1变为C-E1；只能写“暂未发现严格案例” |

## 不把所有追加Prompt都算作模型失败

追加信息分两类：

| 类型 | 示例 | 是否计入用户纠偏负担 |
|---|---|---|
| 业务口径演进 | 用户后来新增“最好无实控人”或把一致行动改成特定方向的委托 | 否；这是研究问题真实变化 |
| 流程纠偏Prompt | 用户重复要求分层、排除表面相似案例、回到一手文件、重新评价旧候选 | 是；这些本应由Skill稳定执行 |

面试汇报时只把第二类计入“Prompt负担减少”，避免为了证明效果而把正常需求澄清算成产品缺陷。

## 当前观察结果

| 观察维度 | GPT-5.6-sol通用检索 | GPT-5.6-sol + Codex Skill |
|---|---|---|
| 基础模型 | GPT-5.6-sol | GPT-5.6-sol |
| 初始案例组织 | 倾向先给候选，未稳定形成严格/近似/排除层 | 先形成必要条件，再按匹配度与证据度分层 |
| 微电生理发现 | 初期未命中 | 口径加入无实控人和直接关系后迅速命中 |
| 近似案例控制 | 强一、埃泰克等需要用户继续复核 | 按实控人和直接关系条件降级 |
| 口径变化处理 | 依赖对话中继续叠加上下文 | 通过S版本和必要条件矩阵全量重排 |
| 协议方向 | 需要用户进一步强调 | 将“主体A → 法律关系 → 主体B”作为固定检查 |

## Pilot评分方式

每个节点按现有100分Rubric评分，同时记录：

- `First-pass strict hit`：首次完整回答是否得到正确A-E1；
- `Layering pass`：是否无需用户要求就给出严格、近似、排除和待核验层；
- `Correction prompts`：流程纠偏Prompt数量；
- `Scope prompts`：真实业务口径变化数量，单列但不作为模型失败；
- `False positive count`：曾列入严格候选、之后因硬条件冲突被排除的案例数量；
- `Condition-cell accuracy`：P01—P06必要条件矩阵的正确单元格比例；
- `Primary-source coverage`：关键事实的一手证据覆盖率。

## 当前可报告与不可报告

可以报告：

> 在同为GPT-5.6-sol的微电生理Pilot中，加载Skill的Codex在明确“无实控人+直接一致行动”后命中Gold案例，并能对旧候选进行动态降级；通用ChatGPT需要额外的流程性Prompt才能完成相同的分层、排除和证据约束。结果说明差异主要来自上下文工程和工作流产品化，而不是更换更强模型。

暂不可报告：

- “准确率提升X%”：尚未完成逐节点盲评和重复运行；
- “检索时间下降X%”：缺少统一时间戳与起止口径；
- “Skill普遍优于ChatGPT”：当前只有一个已知案例族；
- “差异100%由Skill造成”：两种产品环境和工具链仍不完全相同。
