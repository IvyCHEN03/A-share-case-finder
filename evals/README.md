# A-Share Corner Case Finder Evals

本目录用于验证 `a-share-corner-case-finder` Skill 是否真的提高了 A 股边界案例研究质量，而不是只验证模型能否复述一份已知答案。

评测分为三层：

1. **触发层**：面对显式调用、自然语言隐式请求和不应触发的任务，能否正确决定是否使用 Skill。
2. **过程层**：能否先核实现行规则、拆解必要条件、区分严格与宽口径，并回到一手文件读取关键条款。
3. **结果层**：能否基于当前口径动态评级案例、说明升降级和排除理由、使用审慎结论，并给出可复核出处。

## 文件

- `trigger-cases.jsonl`：触发与不触发测试。
- `research-cases.jsonl`：端到端研究测试，包含本次“无实控人 + 外部投资人与员工平台一致行动”案例。
- `rubric.md`：统一评分标准、硬失败项及通过门槛。
- `comparison-protocol.md`：ChatGPT通用、Codex无Skill和Codex加载Skill的三组量化对比方案。
- `pilot-2026-08-13.md`：同为GPT-5.6-sol时，基于今天微电生理任务链形成的六节点纵向Pilot。
- `gold/microport-ep.md`：微电生理基准答案和一手证据锚点。
- `gold/scope-evolution.md`：多轮口径变化下的动态重排基准答案。
- `gold/clarification-policy.md`：偏好条件继续执行与阻塞歧义最少追问的基准答案。
- `gold/cicc-semiconductor-latest.md`：新任务重置、最新性和“最好无实控人”偏好排序的基准答案。
- `gold/ipo-fundraising-implementation-subjects.md`：多实施主体金额披露与境外研发共同实施主体的基准答案。
- `results/retrospective-microport.md`：基于现有对话形成的单案例回溯基线及其结论边界。
- `results/comparison-cicc-semiconductor.md`：两份真实回答在新中金半导体任务下的成对评分与 Skill 优势边界。
- `results/comparison-ipo-implementation-subjects.md`：本次募投实施主体两份回答的成对评分及bad case复盘。
- `interview-scorecard.md`：面试 Demo 观察表，可由面试官或同伴直接打分。
- `validate_evals.py`：检查 JSONL 格式、ID 唯一性和必填字段。
- `test_case_pipeline.py`：对内置下载/PDF校验/动态评级脚本做可重复的冒烟测试。

## 使用方法

### 1. 触发测试

分别在新任务中输入 `trigger-cases.jsonl` 的 `prompt`，不要显式告诉模型预期结果。记录：

- 是否触发 Skill；
- 是否在首次进度更新中明确说明已启用 Skill；
- 不应触发时是否保持克制。

触发测试必须在新任务中完成，避免上一个任务已加载 Skill 造成污染。

### 2. 研究质量测试

将 `research-cases.jsonl` 的 `prompt` 原样输入新任务。允许联网检索，但不要向模型提供 `gold` 文件。完成后依据 `rubric.md` 评分，再与相应 `gold_file` 核对。

为避免答案泄漏，评测执行者只向被测模型提供：

- 原始问题；
- 必要的用户附件；
- 正常可使用的搜索和 PDF 工具。

不要提供预期公司名、判断结论、页码或历史对话。

### 3. 回归测试

Skill、模型或检索工具变更后，至少重跑：

- 全部触发用例；
- `R001` 微电生理严格案例；
- `R002` 两类“或”关系拆分；
- `R003` 候选案例排除；
- `R005` 一手证据不足时的降级处理；
- `R006` 终止项目不得错误归因。
- `R009` 用户连续收紧口径后重新评级和排序。
- `R010` 偏好条件应说明假设并继续，不得无效阻塞。
- `R011` 会改变唯一严格结论的歧义只问一个关键问题。
- `R012` 新检索任务必须重置口径，不得受上一案例硬条件污染。
- `R013` 网络超时或PDF无文字层时，能否程序化重试、转OCR并正确降级证据。
- `R014` 多实施主体项目能否正确区分“逐主体金额”和“只列项目总额”。
- `R015` 能否区分新增共同实施、整体替换、复合项目，并按具体项目核对置换金额。

## 动态评级原则

A/B/C/D只回答“案例和当前问题有多匹配”，不能同时承担证据等级：

| 匹配等级 | 含义 |
|---|---|
| A | 当前严格口径全部满足 |
| B | 缺少可放宽条件，可作为近似参考 |
| C | 违反硬性必要条件，应逻辑排除 |
| D | 信息不足，暂时无法判断 |

口径版本另记S1、S2、S3，证据状态另记E1—E4。评测时必须检查被测回答是否明确当前口径版本，并在条件变化后重新评价所有候选，而不是只把新案例插入旧排名。

## 建议实验设计

为了验证效率提升，而不是只凭主观估算，使用同一组未公开题目进行三组对照：

| 组别 | 工具条件 |
|---|---|
| Baseline A | 人工检索，不使用生成式 AI |
| Baseline B | 通用 ChatGPT/Codex，不加载 Skill |
| Treatment | 同一模型、同一工具权限，加载本 Skill |

每组至少使用 10 道未见题，随机化题目顺序，并记录：

- 总完成时间；
- 首个合格候选出现时间；
- 严格案例准确率；
- 候选召回率（在预先标注的 gold 候选集合上计算）；
- 一手证据覆盖率；
- 误报率和漏报率；
- 严重错误数；
- 人工复核修改时间。

在完成对照测试前，`2 小时降至 20 分钟`只能表述为流程估算或目标，不能表述为已验证的用户效果。

为避免公开 gold answer 造成训练污染，当前公开题主要用于功能回归和面试展示；正式量化结果应另用一组不入库的 holdout 题，并在完成评分前保持答案不可见。

## 发布边界

公开测试集只放公开案例和公开监管文件，不放客户名称、项目底稿或私有研究案例。Skill 发布包本身仍只包含 `SKILL.md`、`agents/` 和 `references/`；`evals/` 不打入安装 ZIP。
