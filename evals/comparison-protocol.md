# ChatGPT通用检索 vs Codex加载Skill：对比评测方案

## 一、评测问题

本评测回答两个不同问题：

1. **产品方案效果**：普通ChatGPT检索与Codex加载本Skill相比，哪一种更快产出可复核的严格案例？
2. **Skill净增益**：在尽量保持模型、工具和原始问题一致时，加载Skill本身带来多少提升？

如果ChatGPT与Codex均使用GPT-5.6-sol，两组对比已经控制了基础模型变量，可用于评估“通用产品方案 vs Skill产品方案”的整体效果。若要进一步把差异严格归因于Skill本身，仍应增加“不加载Skill的Codex”对照组，避免把浏览工具、长任务执行能力或历史上下文差异误归因于Skill。

| 组别 | 条件 | 回答的问题 |
|---|---|---|
| A | ChatGPT通用模型，可正常联网，不提供Skill内容 | 用户日常使用基线 |
| B | Codex，不加载Skill，使用相同原始问题和工具权限 | Codex环境基线 |
| C | Codex，加载A-Share Corner Case Finder | Skill处理组 |

## 二、主指标

### 1. 质量指标

| 指标 | 计算方法 | 越高/低越好 |
|---|---|---|
| 首轮严格命中率 | 首次回答即给出至少一个A-E1案例的题数 ÷ 总题数 | 越高越好 |
| Strict Precision | 正确A类案例数 ÷ 输出为A类的案例总数 | 越高越好 |
| Strict Recall | 正确A类案例数 ÷ Gold中的A类案例总数 | 越高越好 |
| 必要条件准确率 | 判断正确的必要条件单元格 ÷ 全部应判断单元格 | 越高越好 |
| 一手证据覆盖率 | 有一手文件、关键页码支持的关键事实数 ÷ 全部关键事实数 | 越高越好 |
| 动态重排通过率 | 条件变化后正确重评全部候选的轮数 ÷ 条件变化轮数 | 越高越好 |
| 严重错误率 | 出现虚构、协议方向错误、实控人误判等硬失败的题数 ÷ 总题数 | 越低越好 |

### 2. 效率与用户负担指标

| 指标 | 起止口径 |
|---|---|
| 首个合格案例时间TTFC | 从发送原始问题到首次出现A-E1案例 |
| 有效完成时间TTC | 从发送原始问题到首次达到80分且无硬失败 |
| 用户干预次数 | 用户为纠正口径、排除误报、要求分层或补一手证据而新增的消息数 |
| 提示词负担 | 用户追加提示词的总字符数，不含最初原始问题 |
| 无效候选核验量 | 最终被判C的候选中，因模型早期误判而需要用户逐一追问的数量 |

建议用“轮次”作为现有历史对话的回溯指标，用“分钟”作为新盲测的前瞻指标。没有时间戳时不得倒推分钟数。

## 三、单题100分评分

| 维度 | 分值 | 满分条件 |
|---|---:|---|
| 严格案例命中 | 20 | 找到Gold严格案例且未遗漏关键结论 |
| 必要条件与协议方向 | 20 | 主体、直接关系、方向、时点、上市状态和实控人认定均正确 |
| 分层与动态重排 | 15 | 使用S版本、A/B/C/D匹配度和E证据度；条件改变后全量重评 |
| 一手证据 | 25 | 关键事实由已读取的一手文件及页码支持 |
| 误报控制 | 10 | 不把近似结构列为严格命中，逐案解释排除理由 |
| 用户负担 | 10 | 无需用户重复补充Skill已能合理推导的流程要求 |

出现现有`rubric.md`硬失败项时，该题最高40分。

## 四、微电生理题的Gold必要条件

严格问题：无实际控制人的IPO发行人中，上市前存在独立外部投资人与核心团队/员工持股平台直接签署一致行动协议，并最终成功上市。

| 编号 | 必要条件 |
|---|---|
| N1 | 发行人最终成功上市 |
| N2 | 上市前最终认定无实际控制人 |
| N3 | 一方为独立外部投资人 |
| N4 | 另一方为员工持股平台或核心团队持股平台 |
| N5 | 目标双方直接签署一致行动或目标方向的表决权委托 |
| N6 | 不是双方分别与实控人签约，也不是平台内部LP授权GP |
| N7 | 关键事实由一手文件正文支持 |

该口径下，微电生理是Gold A-E1；强一股份、埃泰克、安凯微等因存在实控人或关系结构不同，不得列为严格命中。若问题改为“外部投资人把直接持有发行人股份的表决权委托给员工平台”，微电生理由于协议类型/方向不同应改为C-E1。

## 五、执行SOP

1. 准备至少10道未公开题；公开的微电生理题只用于回归和Demo，不进入最终对外效果数据。
2. 三组使用完全相同的原始问题、附件、时间上限和联网范围。
3. 每题开启新任务，禁止带入上一题上下文；记录模型名称、版本、日期和工具权限。
4. 每组每题至少独立运行3次，用于处理模型输出随机性。
5. 评测者在运行结束前不得提示公司名、页码、分类答案或Gold条件。
6. 保存完整trace：每轮提示、回复、检索来源、时间戳和最终Memo。
7. 两名具备资本市场背景的评分人盲评；分歧项记录原因并复核。
8. 报告中位数和P90，并给出bootstrap置信区间；不要只报告最好一次。

今天逐步发现微电生理的对话属于开发集/回归集，可用于验证bad case是否修复，但不得计入最终holdout效果。对应Pilot见`pilot-2026-08-13.md`。

最小正式样本量为`10题 × 3组 × 3次 = 90次运行`。如时间有限，可先做`5题 × 3组 × 2次 = 30次运行`的探索性测试，但不能据此宣称稳定提升。

## 六、推荐报告格式

| 指标 | ChatGPT通用 | Codex无Skill | Codex+Skill | C相对A变化 | C相对B变化 |
|---|---:|---:|---:|---:|---:|
| 首轮严格命中率 |  |  |  |  |  |
| Strict Precision |  |  |  |  |  |
| 必要条件准确率 |  |  |  |  |  |
| 一手证据覆盖率 |  |  |  |  |  |
| TTFC中位数 |  |  |  |  |  |
| TTC中位数 |  |  |  |  |  |
| 用户干预中位数 |  |  |  |  |  |
| 严重错误率 |  |  |  |  |  |

效果变化统一使用：

```text
绝对提升 = Treatment - Baseline
相对提升 = (Treatment - Baseline) / Baseline
耗时下降率 = (Baseline时间 - Treatment时间) / Baseline时间
干预减少率 = (Baseline干预次数 - Treatment干预次数) / Baseline干预次数
```

当Baseline为0时只报告绝对提升，不计算相对提升。
