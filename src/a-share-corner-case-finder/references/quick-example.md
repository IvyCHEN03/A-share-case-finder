# 新手完整示例

## 用户问题

```text
有没有IPO研发中心项目在首发时由境内主体实施，上市后新增境外共同实施主体的成功案例？
```

## 1. 先把问题拆清楚

```text
必须满足：IPO募投项目；研发中心项目；首发时仅有境内实施主体；上市后新增境外共同实施主体；原境内主体保留。
排除：再融资新项目、非研发项目、境内主体整体替换为境外主体。
截止日：2025-12-31。
```

不确定项不会先伪装成结论；先搜候选，再核对原方案与变更方案。

## 2. 找候选并建立两段证据链

先核实募集资金用途及实施主体变更的现行规则，再搜索“IPO + 研发中心 + 新增/增加实施主体 + 境外”。

每个候选至少需要：

1. IPO招股书：证明首发时的项目、主体和地点；
2. 上市后变更公告或保荐核查意见：证明新增境外主体、原主体是否保留、变更时间和资金安排。

## 3. 用脚本取文件和检查 PDF

```bash
python3 scripts/case_pipeline.py fetch \
  --url "<交易所PDF>" \
  --url "<巨潮镜像PDF>" \
  --output /tmp/case.pdf

python3 scripts/case_pipeline.py inspect /tmp/case.pdf
```

若返回 `scanned_or_sparse`，渲染控制权相关页并 OCR，再对照页面图像核对数字和主体名。

## 4. 候选较多时再自动评级

```bash
python3 scripts/case_pipeline.py schema > /tmp/cases.json
# 编辑 /tmp/cases.json，录入每个候选的条件结果和一手出处
python3 scripts/case_pipeline.py classify /tmp/cases.json --output /tmp/ratings.json
```

脚本仅机械执行已定义的条件；主体性质、法律关系和规则适用仍由研究者核实。

JSON 顶层填写真实 `as_of_date`，并在每个案例的 `dates` 中记录招股书、上市和变更日期。脚本会拒绝未来截止日，或晚于截止日的案例事件。

## 5. 快速交付示例

```text
结论：截止2025年12月31日，联特科技可作为严格案例。
严格案例：IPO招股书显示“联特科技研发中心建设项目”原由境内发行人实施；2024年变更文件新增马来西亚全资孙公司为共同实施主体，原境内主体继续保留，并分别披露境内外主体拟使用募集资金金额。
近似/排除：若原境内主体被整体替换，应列为排除项，不得写成“新增共同实施主体”；复合型“研发中心与信息化”项目应单列限制。
来源：招股书证明原方案；变更公告/保荐核查意见证明新增主体、金额和审批时间。
限制：本结论只覆盖已核验的一手文件，不等于全市场不存在其他案例。
```

一手文件示例：

- 联特科技IPO招股说明书（2022-08-29）：https://static.cninfo.com.cn/finalpage/2022-08-29/1214427506.PDF
- 海通证券关于联特科技变更募投项目实施方式的专项核查意见（2024-03-20）：https://disc.static.szse.cn/disc/disk03/finalpage/2024-03-20/3a81154d-4ffc-438d-b73c-274818dbc560.PDF

示例日期均为历史日期。真实交付仍必须重新联网核对现行规则、项目状态、文件内容和检索截止日。

完整表格交付使用 `case-output-template.md`。
